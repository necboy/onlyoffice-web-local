# PPT 连续预览的缓存与绘制

连续预览通过当前单机 SDK 的页面模型绘图，不重新下载或转换文件，也不改变编辑页码、批注选区或保存流程。

文档就绪并不保证所有页面布局和异步字体/图片都已稳定。此前只凭画布宽度和 `data-rendered` 跳过重绘，可能把首次的白色画布长期缓存。原生单页和连续预览切换后恢复显示，是缓存失效缺失的表现；字体 404、文件接口 401 和编辑器模块加载超时仍需分别排查，不能用重绘掩盖文件加载失败。

## 缓存失效

`ppt-preview.ts` 继续使用既有 SDK 适配，订阅 `asc_onDocumentChanged`（本版 SDK 逐页重算会发出此事件）和 `asc_onEndAction`。收到更新后增加内容版本，原位重绘附近页面，不重建 DOM、不改变滚动或选中页。缓存键包含像素宽、高和内容版本，因此比例、DPR 或内容变化均可更新。

SDK 的二进制字体通过 XHR 加载，不能仅依赖 `document.fonts`。本编辑器内的 PerformanceObserver 观察字体/图片资源完成，FontFaceSet 的 `loadingdone` 和恢复页面可见也会失效缓存。没有 PerformanceObserver 的浏览器仍保留 SDK 通知和有限补绘。

每页首次绘制及版本变化后，在首次绘制的 200、800、2400 毫秒之后各允许一次补绘，覆盖 SDK 布局的晚到阶段；超过此窗口的资源/重算通过通知再触发。真正空白的幻灯片同样会停止补绘，不通过像素颜色猜测加载成功，不使用无限定时轮询。缓存只在 SDK 绘制调用成功返回后更新；异常沿原路径回退单页。

## 性能与清理

待绘制的页面显示旋转图标和“正在渲染…”占位。首次绘制后即展示内容，提示缩为右下角小标记，有限补绘完成后自动隐藏；已有内容的资源更新不重复显示提示，避免闪烁。离屏位图释放后恢复占位，重新进入时随绘制恢复。页面通过 `aria-busy` 表达处理中，动画装饰不逐页播报；尊重减少动态效果偏好，仅邻近视口的加载图标运行动画。提示反映本预览的绘制/补绘阶段，不代表所有外部资源均已下载成功。

先读取布局，再按当前视口、前后邻近视口的顺序绘图。单帧最多两页，绘完一页耗时达到 12 毫秒时把后续绘制让到下一帧；单页内部 SDK 耗时无法中途抢占。滚动、尺寸及 SDK 连续事件合并到一个待处理 animation frame，不连续取消已排队的绘制。

远离视口的位图释放为 1×1，并清除相应缓存，保留 CSS 占位高度。退出连续模式释放位图和补绘定时器；页面隐藏停止补绘，恢复时更新。卸载注销 SDK/字体/可见性监听，断开资源和尺寸观察器，清理 RAF、定时器与缓存。

## 验证

```sh
node --test tests/ppt-preview-cache.test.cjs
PLAYWRIGHT_HEADLESS=1 pnpm exec playwright test e2e/ppt-preview.spec.ts --project=chromium --workers=1
```

浏览器回归覆盖首次未就绪的画布自行恢复、稳定后停止补绘、迟到 SDK/字体资源通知、位图回收和退出模式停止绘制。可另设 `PPT_PREVIEW_FIXTURE=/path/to/deck.pptx` 检查非空白的第 11/12 页；测试只在本机拦截返回文件，不向外部服务上传，私有文件不进入仓库。它使用真实转换器和 SDK，直接滚动连续预览验证像素，不依赖先切单页恢复。

发布需重新构建单机预览服务；无需更改 MantisBot 文件 API、权限或数据存储。部署后的网络、真实文件授权及 CDN 缓存须在现场继续核实。
